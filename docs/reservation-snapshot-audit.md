# Offline reservation snapshot comparison (preparation only)

Run `python -B scripts/reservation_snapshot_audit.py before.json after.json`.
Each input is a local UTF-8 JSON object mapping exact collection IDs to complete arrays of exported records. `Bookings` and `BookingSummary` are mandatory. Additional collections must be present on both sides. Every record needs its original nonempty string `_id`; duplicates are rejected, not overwritten. Nested JSON duplicate keys and nonfinite numbers are rejected. No identifier/date normalization or metadata exclusion occurs.

Exit codes: 0 = supplied records identical by identity and field values, ignoring object key/record order; 1 = added, missing or changed records; 2 = invalid/unreadable input. Array order and exact JSON numeric token spelling are preserved in CLI comparison, including nested values: `1`, `1.0`, `1.00`, and `1e0` differ, as do `-0` and `0`. Number tokens remain distinct from strings and booleans; no binary-float rounding or decimal normalization is used for equality. Nonzero underflow tokens are retained. Decimal/exponent tokens that overflow binary-float range remain rejected for compatibility (for example `1e999`); that range check is not a comparison conversion. Direct Python callers retain their supplied JSON-compatible types, but cannot recover numeric spelling or precision already lost before calling. Missing fields differ from null. All statuses, including Blocked and Cancelled, are compared without filtering. Output includes stable IDs and changed field names, not field values. IDs/field names can themselves be sensitive: protect the output. This is not an anonymization tool.

Always emits `publicationReady: false`. Matching supplied snapshots does NOT establish complete/fresh exports, coherent multi-collection capture, correct Bookings/Summary date alignment, valid occupancy, accepted-price authority, approved migration, rollback compatibility, or absence of external effects. No API/network calls, datastore writes, migration, corrections, or publishing are implemented. Both input files are read-only. Inputs must be trusted-size local exports; this is not a public upload parser or streaming large-data tool.

This closes only the identity/full-field delta-comparison prerequisite of R3/R8. An approved cutover must independently establish complete paginated exports, pause or delta capture, protected manifests/checksums, business-field reconciliation, and all-writer/recovery compatibility. Do not use an empty Sandbox export as live-reservation evidence. No actual live data was exported or evaluated during development.

Known live owner-reported compatibility issues remain separate: WC-1004 Bookings March 6–14 versus Summary March 5–13 2027; ignored Blocked occupancy; misleading minimum-stay message. This comparator detects between-snapshot edits but does not resolve these cross-collection/business-rule issues. Leave legacy live Search unchanged.
